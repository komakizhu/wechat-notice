# 通知的共同语义理解

这份规则由主入口、lite 和 diagram 共用。主入口调用时，每个事项只执行一次；子 Skill 接收同一份结果，只核对自身产物是否忠实表达，不另做一套理解。子 Skill 独立调用时，先完成资料读取与核对，再执行本规则。

先理解整条通知的目的和语义，不能用关键词、节点数量、文案模板或图形模板代替上下文。内部理清：通知是在告知、邀请、征集、提醒还是布置任务；群内读者与实际行动对象分别是谁；哪些参与自愿，哪些事项对特定对象必须执行；行动在哪些条件下成立；每项时间、材料和渠道分别约束哪一个动作。

再识别动作间的实际关系：确有先后依赖的动作串行；互相独立的材料或动作并行；互斥端口与条件选择分支；完成条件只取原文明示内容。不同端口各自保留步骤，不拼成一条顺序链。不能仅因出现比赛或报名就认定自愿，也不能仅因有截止就认定全员必办。关系不明且影响办理时列待确认，不擅自连线。

保留“谁在什么条件下需要或可以做什么”的完整关系。面向群成员的自愿邀请与参与者的办理义务分别表达；不能把参与者的提交义务扩大到全体，也不能弱化明确的必办要求。缺失字段内部保留为未知，不补造事实；对外产物不输出无关办理字段或“未说明／未提供”占位信息，必要缺口在审核说明中列出。

基于已读取材料形成一份共同语义结果：事项与目的、群内读者及行动对象、自愿/必须性质与依据、行动条件、材料、每个动作及其先后/并行/选择关系、各日期与渠道所约束的动作、来源明确的完成条件，以及来源位置、冲突和待确认点。时间使用核对过的原文适用时间或用户明确确认的新时间；未经确认的提前收交建议单独保存，不成为行动要求。这是内部工作上下文，不要求新增数据库结构或向用户展示推理过程。

信息搜索与核对完成后才执行完整语义理解。为判断附件相关性或暂分事项进行的初步阅读不算重复的完整分析。共同语义结果完成后，正文和图示两个分支都复用它：lite 负责措辞、格式与压缩，diagram 负责布局、节点与箭头。两个分支都须逐项核对语义是否保持一致。发现漏读材料、冲突或理解缺口时返回共同阶段补齐并更新同一份结果，再重新生成受影响产物；不得在某一个分支里悄悄另作解释。
