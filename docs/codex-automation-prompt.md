# Codex 提醒唤醒说明

下面的文字用于配置 Codex 内置自动化的每日唤醒。它只检查本地数据并生成待审核内容，不操作微信、不发送消息。

```text
每天在 Asia/Shanghai 09:00 检查项目 `/Users/mac2/Documents/ChatGPT/微群Agent接入计划/data` 中的通知提醒。

执行：
cd '/Users/mac2/Documents/ChatGPT/微群Agent接入计划' && \
  .venv/bin/python -m wechat_notice reminders \
  --data-root '/Users/mac2/Documents/ChatGPT/微群Agent接入计划/data'

如果没有到期提醒或状态没有变化，保持安静。
如果命令返回待审核提醒，在当前任务中展示事项、班级截止时间、提醒文案、对应原件路径和审核状态，并等待用户审核。
如果命令返回 overdue，只提示一次逾期事项，不生成截止前提醒。
不要读取微信、切换微信窗口、发送文字、发送文件或创建其他自动化。
不要把提醒生成、复制文件或函数返回值说成已经发送到微信群。
用户修改截止时间或取消事项后，下一次检查以 SQLite 中的最新状态为准。
```

配置前应先确认当前项目的实际工作目录和 `.venv/bin/python` 已存在。休眠、离线恢复和精确触发时间需要在真实环境中单独验证。

## 消息监控模板（当前只提供提示，不自动创建）

消息监控频率尚未由用户确认。建议先以每 10 分钟一次作为候选值；频率越低越省资源，但窗口读取受限或微信未运行时漏读风险越高。实际自动化创建前，必须填入用户明确指定的源群，并先完成一次后台读取能力验证。

```text
按已确认的监控频率检查指定源群。先调用 check_wechat_capabilities；若微信未运行、后台读取未验证或读取需要抢前台，保持安静并报告限制。只读取用户指定源群和有限窗口，调用 fetch_messages_by_chat，保留 complete、stop_reason、missing_fields 和 batch_id。将稳定消息标识交给 monitor-once 做增量处理；没有稳定标识的消息不自动去重。发现新消息后读取其中明确的 HTTP(S) 链接、公众号图片和已登记附件，生成待审核通知包；不切换窗口、不发送、不把函数返回当作送达证明。没有新消息或状态没有变化时保持安静。
```
